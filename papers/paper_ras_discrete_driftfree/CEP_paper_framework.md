# CEP 论文框架

## 0. 先讲清楚底线

这份框架用于指导论文故事与初稿撰写，但必须先明确一条底线：

> 在当前只有离线仿真与 CoppeliaSim 实时控制循环验证的情况下，这篇稿子仍然只是预投稿版本，而不是可直接投递给 *Control Engineering Practice* 的最终版本。

原因很简单。CEP 的关键词是 **Practice**。对这类期刊而言，真实 UR3e 平台验证不是锦上添花，而是进入外审前最重要的工程支撑之一。因此，最终投递版本必须把真实机械臂实验写成正文高潮，而不能仅仅写成“未来工作”或“预留协议”。

这意味着当前框架要承担两个任务：

1. 先把论文的理论故事、方法层级和仿真证据讲清楚。
2. 同时为后续真实 UR3e 实验预留清晰的插入位置与叙事接口。

另外要注意一个写作层面的细节：当前“尚无真实 UR3e 实验”这一事实，应该在实验设计、结果讨论和工作清单里坦诚交代，而不应写进摘要。摘要必须像一篇完整论文那样，只讲问题、方法、理论与现有证据。

## 1. 文章核心故事

这篇稿子的核心不应当是“谁的绝对精度最高”，而应当是：

1. 经典无漂移重复运动学求解方案，主要是在连续时间神经动力学语境下建立起来的。
2. 真实机器人控制是采样执行的，因此存在一个从连续时间方案走向离散控制实现的结构错位问题。
3. 原始三种方法中，`Method 3a` 的确有最高的原始精度，但它是通过更改外层目标函数得到的。
4. 如果坚持保留**经典无漂移运动学解析范式**，那么 `Method 2` 是最强、最干净、最值得继承的基线。
5. 因而本文主贡献不是单纯追求更低误差，而是将 `Method 2` 这一经典解析范式，落实为一个真正适配采样控制的 `Method 2 DLCCZNN`。
6. `Method 3a PCG` 可以作为强参考，但它属于另一条“离散目标函数优化”路线，因此不能喧宾夺主。
7. `Method 3c LCCZNN` 的失败恰好反证了本文主张：对于漂移抑制这类闭环周期性质问题，求解器与控制结构必须紧耦合设计，而不能做算法与结构的解耦替换。

一句话概括全文主叙事：

> 本文研究的不是“哪一个方法在当前数据下误差最小”，而是“如何将经典无漂移运动学解析范式从连续时间思路，稳健地带入采样机器人控制，并在此过程中保持漂移抑制的闭环性质”。

## 2. 贡献排序

### 第一贡献

提出 `Method 2 DLCCZNN` 作为主方法：

- 它保留经典等式约束解析范式。
- 它的内层不是连续时间神经动力学的简单移植，而是采样实现下的 KKT 残差跟踪器。
- 它把“有限计算预算内的离散求解”纳入控制设计本身。

严格地说，第一贡献不能写成“DLCCZNN 本身”，因为 DLCCZNN 不是这篇文章首次提出的工具。真正应当凸显的是：

> 将 DLCCZNN 以解析范式保持的方式引入经典 drift free QP，并形成可采样实现的主控制器。

### 第二贡献

从采样控制视角重新解释经典无漂移运动学解析范式，明确：

- 为什么约束中要使用任务反馈速度，而不是纯任务速度。
- 一步位置误差与一步角度漂移误差如何传播。
- 动态速度边界如何由关节物理约束诱导而来。
- 经典解析范式与离散目标函数路线的本质区别是什么。

### 第三贡献

通过一组层次化对比说明“紧耦合设计”优于“算法与结构的解耦替换”：

- 原始 `Method 1 / Method 2 / Method 3a`
- `Method 1 DLCCZNN`
- `Method 2 DLCCZNN`
- `Method 3c LCCZNN`
- `Method 3a PCG`

### 第四贡献

建立从离线、实时控制循环验证到真实 UR3e 平台验证的统一实验模板，使论文同时具备理论逻辑、控制解释和工程落地接口。

## 3. 术语规范

为了避免论文中出现不够正规或口语化的表达，建议统一采用以下术语。

- “壳层”
  统一替换为：
  **经典无漂移运动学解析范式**
  或
  **classic drift free kinematic resolution formulation**

- “壳层保留”
  统一替换为：
  **解析范式保持**
  或
  **formulation preserving**

- “盲目换求解器”
  统一替换为：
  **算法与结构的解耦**
  或
  **algorithmic structural decoupling**

- “结构匹配”
  统一替换为：
  **紧耦合设计**
  或
  **tight algorithmic structural coupling**

- “Live 仿真”
  如果是真实硬件在环，不妨使用：
  **hardware in the loop validation**

  但当前你的实验仍然是 CoppeliaSim 远程 API 同步控制，不应误称为硬件在环。
  因此更准确的表述应为：
  **simulator based real time control loop validation**
  或
  **real time control loop verification in CoppeliaSim**

## 4. 章节结构

## Section 1 Introduction

目标是先立问题，再立冲突，再立主方法。

必须完成四件事：

1. 引出冗余机械臂重复运动中的 joint drift 问题。
2. 点明经典工作主要来自连续时间神经动力学语境。
3. 明确提出本文关心的是“连续时间方案如何进入采样控制”的问题。
4. 提前交代本文为什么选择 `Method 2 DLCCZNN` 作为主线。

引言中最关键的一句话应当是：

> 当问题从连续时间规划转入采样控制执行时，研究焦点不再只是求解精度本身，而是控制结构与离散求解动态之间是否保持一致。

## Section 2 Related Work

建议分成三条线：

1. drift free repetitive motion planning
2. neural dynamic solvers for constrained inverse kinematics
3. LCCZNN / DLCCZNN and sampled robot control

这一节的任务不是堆文献，而是为本文主叙事清障：

- 说明经典无漂移解析范式的历史地位。
- 说明神经网络求解器并不是新鲜话题。
- 说明本文真正新意在于“采样控制重述 + 解析范式保持 + DLCCZNN 落地”。

## Section 3 Problem Formulation

这一节应当先给出一个系统级控制框图，再给公式。

建议包含以下内容：

1. 冗余机械臂运动学。
2. 位置误差与漂移误差定义。
3. 一步离散误差传播。
4. 任务反馈速度为什么必要。
5. 动态速度边界的物理来源。
6. 经典解析范式与离散目标函数路线的分界。

这一节的作用是把整篇论文最重要的两条路线明确分开：

- 解析范式保持路线
- 目标函数重写路线

## Section 4 Classic Formulations and Proposed Controller

这一节不要把大量辅助方法写得和主方法一样重。

推荐结构：

1. 原始 `Method 1` 与 `Method 2`
   只写到足够支撑后续比较即可。
2. 原始 `Method 3a`
   用来说明“目标函数重写路线”的强参考。
3. `Method 2 DLCCZNN`
   全力展开，作为全文核心方法。
4. 其余方法只保留最简说明
   `Method 1 DLCCZNN`、`Method 3c LCCZNN`、`Method 3a PCG`
   只说明它们是什么，不必在这一节过度铺陈。

换句话说，Section 4 的资源分配必须明显偏向 `Method 2 DLCCZNN`。

## Section 5 Discrete Time Analysis

这一节必须从“讲概念”升级为“给离散时间证明”。

最低要求应包括：

1. KKT 根与优化解的一致性。
2. 内层 DLCCZNN 采样更新的离散 Lyapunov 型收敛不等式。
3. 外层位置误差传播的离散时间有界性分析。
4. 残差到控制误差、控制误差到跟踪误差之间的链式关系。
5. 复杂度分析只放在这些证明之后，作为工程补充而不是理论主角。

更直白地说：

这一节一定要让审稿人看到你不是在“讲一个像控制的故事”，而是在给一个离散控制定理链条。

## Section 6 Experimental Setup

建议拆成五部分：

1. 平台与轨迹
2. 方法分组
3. 参数设置
4. 调参协议
5. 当前状态与必须补上的真实 UR3e 验证

这里一定要说清楚：

- 离线仿真只是理想 replay。
- CoppeliaSim 同步控制循环只是实时执行近似验证。
- 真实 UR3e 实验才是最终 CEP 投递版的关键工程验证。

## Section 7 Results and Discussion

建议拆成五个问题驱动的小节：

1. 哪个基线应该作为本文锚点
2. 经典解析范式能否在实时执行中被真正改进
3. 为什么最终参数组合是科学合理的
4. 为什么紧耦合设计比单纯的低复杂度更重要
5. Method 3 这条线该如何定位，以及真实实验还缺什么

这一节要做到三点：

- 图表服务论点，而不是图表堆砌。
- 把 `Method 2 DLCCZNN` 的故事讲成主线。
- 把 `Method 3a / PCG` 的强结果讲成“边界参照”而不是“竞争主线”。

## Section 8 Conclusion

结论必须收束到三点：

1. 本文完成的是对经典无漂移运动学解析范式的离散控制化增强。
2. `Method 2 DLCCZNN` 是当前解析范式保持路线中最有说服力的主方法。
3. 在最终 CEP 版本中，真实 UR3e 实验必须成为全文收束点。

## 6. 审稿人视角下最重要的回答

### 审稿人可能问：为什么主方法不是精度最高的 Method 3a

回答逻辑：

- `Method 3a` 改变了外层目标函数。
- 本文主问题不是谁绝对精度最高，而是经典解析范式如何适应采样控制。
- 在这个主问题下，`Method 2 DLCCZNN` 是最干净、最一致、最能自圆其说的主方案。

### 审稿人可能问：PCG 效果很好，为什么只是辅助

回答逻辑：

- `PCG` 是求解 `Method 3a` 离散子问题的强参考。
- 它回答的是“如何更好地解离散目标函数”。
- 但它并不回答“如何将经典无漂移解析范式离散控制化增强”。
- 因此它应被定位为边界参照，而不是主贡献。

### 审稿人可能问：为什么 Method 3c 会失败

回答逻辑：

- 漂移抑制是闭环周期性质，不是单步位置误差性质。
- 直接把 LCCZNN 套入 `Method 3a` 的线性方程，相当于做了算法与结构的解耦替换。
- 这种替换可能保住瞬时位置精度，却保不住周期末端漂移恢复。
- 这正好支持本文关于“紧耦合设计”的核心主张。

### 审稿人可能问：没有真实 UR3e 实验为什么还想投 CEP

回答逻辑不应当是狡辩，而应当是动作清单：

- 当前稿件只能作为预投稿框架与理论仿真稿。
- 真正投递 CEP 前必须补齐真实 UR3e 实验。
- 补实验时应直接沿用当前控制图、参数组、评价指标与表格模板。

## 7. 目前最应该做的事

如果目标是让这篇稿子真正具备 CEP 投稿潜力，优先级应当是：

1. 继续把 Section 5 打磨成离散时间稳定性分析，而不是停留在概念解释。
2. 保持 `Method 2 DLCCZNN` 作为唯一主角，不让 `Method 3a / PCG` 抢戏。
3. 把真实 UR3e 通信、采样周期、数据采集与轨迹回放实验尽快跑通。
4. 在真实实验完成之后，再做最终语言压缩与版式打磨。

结论只有一句话：

> 这篇文章真正吸引审稿人的地方，不是“我们又跑出了一个更低误差”，而是“我们把经典无漂移解析范式成功且可解释地带入了采样机器人控制，并证明了只有紧耦合设计才能保住漂移抑制这一闭环性质”。
