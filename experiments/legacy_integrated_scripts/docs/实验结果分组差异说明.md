## 2. 三类结果本来就不是同一口径

在当前脚本里，至少有三种常见结果组：

| 结果组 | 含义 | 主要用途 |
| --- | --- | --- |
| `offline_one_cycle` | 纯数学离线积分，只看第 1 个周期结束时的终点减起点 | 看算法本身的数值精度 |
| `offline_20_cycles` | 纯数学离线积分，连续跑 20 个周期后再做终点减起点 | 看长期重复运动后的漂移累积 |
| `live_one_cycle` | 真实连接 CoppeliaSim 做闭环执行，只跑 1 个周期 | 看控制器加仿真执行后的真实闭环效果 |

所以：

- `offline_one_cycle` 不能直接和 `offline_20_cycles` 当作同一实验看；
- `offline_one_cycle` 也不能直接和 `live_one_cycle` 当作同一精度层级看；
- 同一个方法在这三组里的数值不同，本身就是正常现象。

## 3. 为什么“相同实验”在不同组里精度差很多

常见原因一共有四类。

### 3.1 原因 1：实验模式根本不同

`offline` 和 `live` 的误差来源不同。

`offline` 只有：

- 建模误差；
- 离散化误差；
- 求解器数值误差。

`live` 还会额外包含：

- CoppeliaSim 内部执行误差；
- 目标关节位置接口误差；
- 同步触发与反馈读取延迟；
- 外层 `tau` 与仿真内部积分步长不完全一致带来的误差。

所以同一个方法常见情况是：

- `offline` 更理想，误差更小；
- `live` 更接近真实闭环，误差更大。

### 3.2 原因 2：统计口径不同

单周期漂移和 20 周期累计漂移不是一回事。

例如：

- `theta(T)-theta(0)` 看的是一个周期末尾漂移；
- `theta(after 20 cycles)-theta(0)` 看的是长时间重复运动后的累计偏移。

前者回答“单周期末尾偏了多少”，后者回答“长期反复做会不会越漂越远”。

### 3.3 原因 3：旧版摘要脚本曾有过一次口径 bug

旧版脚本里：

- `offline_one_cycle` 的平均位置误差，误用了多周期汇总值。

这已经在新版脚本中修正。

因此：

- 旧目录里一部分“单周期平均位置误差”会显得异常；
- 新目录 `20260409_095702` 才是修正后的可信版本。

### 3.4 原因 4：旧版目录名只有秒级时间戳

如果两次运行在同一秒内启动：

- 不同实验可能落入同一目录；
- 看起来像一组结果，实际上混了多次运行；
- 这会造成“同名实验文件里参数看起来不一致”的现象。

这个问题现在已经修掉：

- 新版脚本改成了“带微秒”的目录名；
- 同时每次运行都会额外生成 `experiment_metadata.json`。

## 4. 现在应该怎样正确比较结果

建议按下面顺序比较：

1. 先看 `offline_one_cycle`
   目的：比较算法本身的理论数值精度。
2. 再看 `offline_20_cycles`
   目的：比较长期漂移累积能力。
3. 最后看 `live_one_cycle`
   目的：比较真实闭环执行能力。

不要做下面这些比较：

- 不要把 `offline_20_cycles` 和 `live_one_cycle` 直接比大小；
- 不要把 smoke test 目录和正式目录混用；
- 不要把旧目录 `20260408_231231` 当正式数据源。
